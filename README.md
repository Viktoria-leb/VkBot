Результаты проекта:
- Реализована трёхзвенная архитектуру приложения  с чётким разделением ответственности: слой представления отвечал только за взаимодействие с пользователем, бизнес‑логика — за валидацию и обработку сценариев, слой доступа к данным — за сохранение и чтение конфигурации и истории задач.
- Настроена интеграция с VK API через Long Poll: организован непрерывный опрос сервера, обработку входящих сообщений, автоматическое переподключение при ошибках и парсинг полезной нагрузки в DTO‑объекты для дальнейшей обработки.
- Разработано система командного управления ботом: реализовал диспетчер команд на базе интерфейса и enum, где каждая команда инкапсулировала свою логику (старт, настройка фильтров, обновление/удаление задачи и т. д.), а диспетчер определял подходящий обработчик по тексту сообщения.
- Внедрена гибкая система фильтрации вакансий: пользователь мог задавать критерии по региону (через код или кнопки), минимальному опыту, минимальной зарплате и ключевым словам; все фильтры применялись по логике «И», а ввод поддерживался как через интерактивные кнопки, так и через команды  и др.
- Реализована интеграция с API агрегатора вакансий: настроена отправка GET‑запросов с динамическими параметрами, обработку пагинации и преобразование JSON‑ответов в Java‑объекты с помощью библиотеки Jackson.
- Добавлена бизнес‑логика нормализации и фильтрации данных: для вакансий без параметра зарплаты, реализована пост‑фильтрация по заданному пользователем минимуму; учитывал формат ISO для дат; корректно обработано смещение (offset) и лимиты для получения полного набора релевантных вакансий.
- Организовано хранение пользовательских настроек и задач в файловой системе: спроектировал и реализовал репозитории на основе JSON‑сериализации, где данные сохранялись с привязкой к ID пользователя из VK; обеспечено сохранение истории запросов, фильтров и статуса задач, чтобы после перезапуска бота все настройки восстанавливались.
- Настроено выполнение фоновых задач по расписанию, реализованы ежедневный поиск новых вакансий и отправку уведомлений пользователям; внедрен механизм отмены задач при удалении заявки пользователем, а также хранение запланированных задач в Map по ID пользователя для быстрого доступа и управления.
- Обеспечена обработка ошибок и нештатных ситуаций: добавил собственные бизнес‑исключения для сценариев вроде «заявка не создана» или «некорректный формат команды», реализована обработка сбоев сети и ответов API с кодами ошибок, а также понятные сообщения для пользователя в чате VK.
- Подключена система сборки Gradle и структурирован проект по пакетам в соответствии с архитектурой; покрыты ключевые компоненты юнит‑тестами (валидация фильтров, парсинг JSON, логика диспетчера команд, работа планировщика) с покрытием не менее 80%.
